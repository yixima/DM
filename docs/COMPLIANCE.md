# 法令・マナー面の整理

このシステムは日本国内の B2B 向け営業連絡を想定しています。以下は運用にあたっての整理であり、
法律上の助言ではありません。**判断に迷う点は自社の法務・顧問弁護士に確認してください。**

---

## 1. メール配信 — 特定電子メール法

### オプトイン規制と、その例外

広告宣伝メールは原則として**あらかじめ同意を得た相手にしか送れません**（特定電子メール法 第3条）。
ただし例外があり、そのうち今回のリストに関係するのは次の2つです。

- **自己のメールアドレスを公表している団体、および営業を営む個人**
  （ただし「広告宣伝メールの送信をしないよう求める旨」を公表している場合を除く）
- 名刺などで自らアドレスを通知した相手

今回のリストは各社ウェブサイトで**公開されている**問い合わせ先を集めたものなので、
法人・個人事業主宛であれば、この例外に該当し得ます。ただし次の点に注意してください。

- **相手のサイトに「営業メールお断り」の記載がある場合は例外に当たりません。** 送らないでください。
  該当先を見つけたら `dm suppress --kind domain --value <ドメイン>` で登録します。
- **個人宛のアドレス（フリーメール等）は例外の適用が弱くなります。** リストには
  フリーメール判定が154件あります。慎重にいくなら
  `config/settings.yaml` の `quality.exclude_freemail: true` で一律除外できます。

### 表示義務（第4条）— 本文に必ず入れるもの

| 項目 | 本システムでの担保 |
|---|---|
| 送信者の氏名または名称 | `templates/email/_footer.txt.j2`。未記載なら送信を中止 |
| 送信者の住所 | 同上。未記載なら送信を中止 |
| 苦情・問い合わせを受け付ける連絡先 | 同上（メール・電話・URL のいずれか） |
| 受信拒否の通知ができる旨とその通知先 | 同上（配信停止URL＋メールアドレス） |

これらは `dm/compliance.py` が**送信直前に実際の本文に対して**検査します。
1つでも欠けていれば、その1通は送らず `skipped_compliance` として記録されます。
警告して送る、という挙動はありません。

### 禁止事項

- 送信者情報の**偽装**（架空の送信元アドレス、他社名の詐称）。本システムは `.env` の値をそのまま
  使い、偽装の手段を提供しません。
- 受信拒否の意思を示した相手への送信。`dm ingest` と `dm suppress` で防ぎます。

### 違反した場合

総務大臣・消費者庁長官による措置命令、法人に対しては最大3,000万円の罰金が定められています。
配信停止の申し出を取りこぼさないこと（＝ `dm ingest` を毎日回すこと）が、実務上いちばん重要です。

## 2. 問い合わせフォームへの自動送信

こちらは**メールほど明確な法規制がない領域**です。だからこそ、運用側で線を引く必要があります。

### 本システムが守っていること

| ルール | 実装 |
|---|---|
| CAPTCHA を回避しない | 検出したら送信中止（`skipped_captcha`）。突破用のコードは一切含みません |
| `robots.txt` を尊重する | 禁止パスには送信しない（`form_limits.respect_robots`） |
| 相手サーバに負荷をかけない | 1件ごとに8秒＋ゆらぎ、同一サイトへは1日1回まで |
| 誰からの連絡か明示する | 本文に社名・住所・連絡先がなければ送信中止 |
| 断る手段を示す | 「今後のご案内が不要な場合は…」の記載がなければ送信中止 |
| 意味の分からない欄を埋めない | 判別できない必須項目があれば送信せず手動対応へ回す |

### 法的な論点

- **業務妨害**: 大量・高頻度の送信が相手の業務を妨げたと評価されれば、偽計業務妨害に問われる
  可能性は否定できません。本システムの既定値（1サイト1日1回・全体で1回60〜150件）は
  この観点から設定しています。**上限を大きく引き上げないでください。**
- **利用規約違反**: 「営業目的の送信を禁止する」と明記しているサイトがあります。これは契約上の
  問題であり、robots.txt では判別できません。**フォームのページに書かれた注意書きは、
  自動判定に頼らず定期的に人が確認してください。** 発見したら `suppress` に登録します。
- **CAPTCHA の回避**: 不正アクセス禁止法の対象となる恐れがあるほか、単純に相手の意思に反します。
  このシステムでは実装しませんし、追加しないでください。

### 運用上のマナー

- 同じ企業に、メールとフォームの両方から同時に送らないこと
  → `global_min_interval_days`（既定3日）でシステム側が防いでいます。この値は下限であり、
  キャンペーン側の設定で下回ることはできません。内容の違うものであれば週2回まで届きます。
  **同じ内容を短期間に繰り返さないことは、運用側で担保してください。**
- 断られた相手に送り続けないこと → 返信を読み、`suppress` に入れること。
- 反応がないからといって頻度を上げないこと。反応がないのは、頻度ではなく内容の問題です。

## 3. 個人情報の取り扱い

- 収集した連絡先は個人情報に該当し得ます（担当者名を含む場合は明確に該当）。
  利用目的を自社のプライバシーポリシーに記載してください。
- `data/*.csv` と `state/dm.sqlite3` は取り扱いに注意し、公開リポジトリに置かないでください。
- 削除依頼を受けたら、`suppress` への登録だけでなく、実データからの削除も検討してください。
