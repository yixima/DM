## 6. 実装済みの機能（2026-08-27 時点）

| 領域 | 内容 |
|---|---|
| リスト取り込み | 正規化・重複統合・不正データの除外（`dm import`） |
| 配信の決定 | ステップ順の進行、最短間隔、ドメイン単位の上限、配信停止の反映（`dm/selector.py`） |
| 並行配信 | 優先度つき。`--campaign all` で複数シリーズをまとめて実行 |
| メール送信 | console / .eml出力 / SMTP。List-Unsubscribe 付与 |
| フォーム送信 | Playwright。CAPTCHA は回避せず中止、robots.txt 尊重、確認画面対応、証跡保存 |
| 法令チェック | 送信直前に本文を検査し、表示が欠けていれば送らない（fail-closed） |
| 到達性チェック | SPF / DKIM / DMARC / 逆引き / From整合を実測（`dm doctor --dns`） |
| 送信量の制御 | 1回あたり・1時間あたり・1日あたりの上限。到達したら翌日へ繰り越し |
| バウンス処理 | IMAP から恒久・一時バウンスと配信停止の申し出を取り込み |
| プレビュー | 全ステップの文面を1ページに書き出す（`dm preview --html`） |
| 定期実行 | systemd timer / cron（多重起動防止つき） |

## 7. よく使うコマンド

```bash
python -m dm.cli doctor --dns                                   # 送信前の設定・認証チェック
python -m dm.cli plan --campaign all --channel email            # 今回誰に何が送られるか
python -m dm.cli preview --campaign <key> --html state/preview.html  # 文面を1ページに書き出す
python -m dm.cli send --campaign all --live                     # メール配信
python -m dm.cli form --campaign all --live                     # フォーム送信
python -m dm.cli ingest --imap                                  # バウンス・配信停止の取り込み
python -m dm.cli stats / runs / campaigns                       # 状況確認
```

テスト実行（フォーム送信のテストには Chromium が必要）:

```bash
DM_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome python -m pytest -q
```

## 8. 注意点・過去に踏んだ問題

- **`git push` が権限で拒否されることがある。** その場合は `git push`（引数なし）で通ることを確認済み。
- この実行環境では **UDP/53 が塞がれている**ため、DNS は HTTPS 経由（DoH）へ自動的に切り替わる。
  ユーザーのサーバでは通常の DNS が使われる。
- `state/` と `.env` は `.gitignore` 済み。送信履歴（`state/dm.sqlite3`）は**バックアップ対象**。
  これを失うと二重送信が起きる。
- `data/*.csv` には取引先候補の連絡先が入っている。リポジトリを公開する場合はリポジトリ外へ移す。
